# What's New in Version 3.9.0

**Released:** February 2, 2026

---

## ✨ Simplified Event Permissions

We've made event permissions easier to understand and use! The permission system has been simplified from 5 roles to 3 clear roles.

### What Changed

**Old Roles (5):**
- OWNER
- MANAGER
- OVERSEER
- KEYMAN
- VIEWER

**New Roles (3):**
- **ADMIN** - Full control over the event
- **COORDINATOR** - Day-to-day management
- **VIEWER** - Read-only access

### What This Means for You

**Your existing permissions were automatically updated:**
- If you were an **OWNER**, you're now an **ADMIN** (same full control)
- If you were a **MANAGER, OVERSEER, or KEYMAN**, you're now a **COORDINATOR** (same management abilities)
- If you were a **VIEWER**, you're still a **VIEWER** (no change)

**Nothing else changed** - you can still do everything you could before. The roles just have clearer names now.

---

## 🎯 What You Can Do with Each Role

### ADMIN (Full Control)
Admins have complete control over the event:
- ✅ Edit event details (name, dates, location)
- ✅ Delete the event
- ✅ Manage volunteers and positions
- ✅ Create and manage assignments
- ✅ Publish documents
- ✅ Grant and remove permissions
- ✅ View all reports

### COORDINATOR (Day-to-Day Management)
Coordinators handle daily event operations:
- ✅ Manage volunteers (add, edit, remove)
- ✅ Create and edit positions
- ✅ Create and manage assignments
- ✅ Publish documents
- ✅ View all reports
- ❌ Cannot edit event details or delete event
- ❌ Cannot manage permissions

### VIEWER (Read-Only)
Viewers can see everything but can't make changes:
- ✅ View event details
- ✅ View volunteers and positions
- ✅ View assignments
- ✅ View published documents
- ❌ Cannot make any changes

## 🐛 Bug Fixes

### Parent Events Can Now Have Multiple Children
Fixed an issue where parent events could only have one child event. You can now create multiple child events under a single parent event, making it easier to organize complex event structures like multi-day conventions.

---

## 💡 What You Need to Know

**No action required!** All existing permissions were automatically converted to the new system. Everything works exactly as it did before, just with clearer role names.

**Key Points:**
- Every event must have at least one ADMIN
- System Admins always have access to all events
- Permissions are set per event (someone can have different roles for different events)
- Volunteers don't need event permissions - they automatically see their own assignments

---

## 🎉 Why We Made This Change

The old 5-role system was confusing because:
- MANAGER, OVERSEER, and KEYMAN all had similar permissions
- It wasn't clear what each role could do
- Most events only used 2-3 of the 5 roles

The new 3-role system is:
- ✅ Easier to understand
- ✅ Clearer about what each role can do
- ✅ Simpler to explain to new users
- ✅ Matches how events are actually managed
